# Latent-Space LLM — Architecture & Training Design## OverviewA conversational language model where reasoning occurs in a compressed latent space rather than token space. The architecture is a three-stage pipeline: an encoder compresses text into a fixed set of latent vectors, a transformer "thinker" reasons over those vectors, and a decoder autoregressively generates the response from the thinker's output.This document is a complete implementation specification. Every design decision is explicit and justified. Do not deviate from these decisions without flagging it.---## Target Hardware & Framework- **GPU:** AMD RX 6700 XT (12GB VRAM) via ROCm- **Framework:** PyTorch (ROCm build)- **Constraint:** No custom CUDA kernels. Use only standard PyTorch ops. Flash attention is off limits unless it has a confirmed ROCm-compatible fallback.- **Total parameter budget:** ~150M  - Encoder + Decoder combined: ~50M  - Thinker: ~50–100M---## Tokenizer- Use a pretrained **BPE tokenizer** — specifically `gpt2` tokenizer from HuggingFace.- Vocabulary size: **50,257** (GPT-2 default)- Do NOT train a custom tokenizer for the MVP.- Special tokens to add:  - `<|user|>` — start of user turn  - `<|assistant|>` — start of assistant turn  - `<|endofturn|>` — end of any turn- Max input sequence length: **512 tokens**- Max output sequence length: **256 tokens**---## Architecture### High-Level Pipeline```[Input tokens]      │      ▼[Token Embedding + Positional Encoding]      │      ▼[Perceiver Encoder]  →  N=64 latent vectors, dim=512      │      ▼[VQ Bottleneck]  →  quantized latents, same shape      │      ▼[Thinker Transformer]  →  N=64 transformed latent vectors, dim=512      │      ▼[Cross-Attention Decoder]  →  autoregressive token generation      │      ▼[Output tokens]```---### 1. Token Embedding```Input: token ids, shape [batch, seq_len]Output: embeddings, shape [batch, seq_len, 512]```- Standard learned embedding table: vocab_size × 512- Sinusoidal positional encoding added (not learned — simpler and sufficient for MVP)- Dropout: 0.1- Parameters: ~25.7M (this is shared — the decoder output projection ties weights back to this embedding table)---### 2. Perceiver Encoder```Input: token embeddings, shape [batch, seq_len, 512]Output: latent vectors, shape [batch, 64, 512]```**Purpose:** Compress variable-length token sequence into a fixed set of N=64 latent vectors. These vectors are the "thoughts" — a compressed semantic representation of the input.**Architecture:**- N=64 learned query vectors, shape [64, 512]. These are model parameters, not derived from input.- 6 transformer layers. Each layer is:  1. **Cross-attention:** The 64 query vectors attend over the full input token embeddings. Standard multi-head attention, 8 heads, head dim 64.  2. **Self-attention:** The 64 query vectors attend over each other. Standard multi-head attention, 8 heads, head dim 64.  3. **FFN:** Two-layer MLP, hidden dim 2048, GELU activation.  4. Layer norm before each sub-block (pre-norm, not post-norm).  5. Dropout 0.1 on attention weights and FFN.- No causal masking anywhere in the encoder. It is fully bidirectional. It reads the entire input context.- Parameters: ~10M**Why Perceiver:** The cross-attention from learned queries to input naturally produces exactly N output vectors regardless of input length. Clean, well-understood, no special ops required.---### 3. VQ Bottleneck (Vector Quantization)```Input: latent vectors from encoder, shape [batch, 64, 512]Output: quantized latents, shape [batch, 64, 512]```**Purpose:** Regularize the latent space. Without this, the encoder produces arbitrary continuous vectors that have no structure, and the thinker has nothing coherent to operate on.**Architecture:**- Codebook: 512 learned vectors, each dim 512. Shape [512, 512].- For each of the 64 input vectors, find the nearest codebook entry by L2 distance.- Replace the input vector with the nearest codebook entry.- Gradient handling: straight-through estimator.  - Forward pass: use quantized vector (codebook entry).  - Backward pass: pass gradient through as if quantization didn't happen.**Implementation (exact):**```pythondef forward(self, z_e):    # z_e: [batch, 64, 512]    # Flatten for distance computation    flat = z_e.reshape(-1, self.dim)  # [batch*64, 512]        # Compute distances to all codebook entries    distances = (        flat.pow(2).sum(1, keepdim=True)        - 2 * flat @ self.codebook.T        + self.codebook.pow(2).sum(1)    )  # [batch*64, 512]        # Nearest codebook entry    indices = distances.argmin(1)  # [batch*64]    z_q = self.codebook[indices].reshape(z_e.shape)  # [batch, 64, 512]        # Straight-through estimator    z_q_st = z_e + (z_q - z_e).detach()        # Losses    commitment_loss = F.mse_loss(z_e, z_q.detach())    codebook_loss = F.mse_loss(z_e.detach(), z_q)        return z_q_st, commitment_loss, codebook_loss```**VQ losses:**- `commitment_loss`: keeps encoder outputs close to codebook. Weight: **0.25**- `codebook_loss`: moves codebook entries toward encoder outputs. Weight: **1.0****Codebook collapse prevention:**- Use exponential moving average (EMA) updates for the codebook instead of gradient descent. This is more stable.- If any codebook entry goes more than N steps without being selected, re-initialize it to a random encoder output from the current batch.- Track codebook usage per step and log it. If fewer than ~30% of entries are active, something is wrong.---### 4. Thinker Transformer```Input: quantized latents, shape [batch, 64, 512]Output: transformed latents, shape [batch, 64, 512]```**Purpose:** Reason over the compressed representation. Operates entirely in latent space — no token vocabulary, no text. Input and output are the same shape and live in the same vector space.**Architecture:**- Standard transformer encoder (bidirectional, no causal mask)- 12 layers- 8 attention heads, head dim 64, model dim 512- FFN hidden dim: 2048, GELU activation- Pre-norm (layer norm before each sub-block)- Dropout: 0.1- No positional encoding — the 64 latent positions are already implicitly ordered by the Perceiver- Parameters: ~50M**Note:** The thinker does NOT have a vocabulary. It does not predict tokens. Its output is a tensor of shape [batch, 64, 512] that the decoder will cross-attend to.---### 5. Cross-Attention Decoder```Input (context): thinker output latents, shape [batch, 64, 512]Input (tokens): previous output tokens, shape [batch, output_seq_len]Output: token logits, shape [batch, output_seq_len, vocab_size]```**Purpose:** Autoregressively generate output tokens, conditioned on the thinker's latent representation.**Architecture:**- 6 transformer layers. Each layer:  1. **Causal self-attention:** Output tokens attend to previous output tokens. Standard causal mask (upper triangle = -inf). 8 heads, head dim 64.  2. **Cross-attention:** Output token representations attend to the 64 thinker latent vectors. No causal mask on the latent side — the decoder can attend to all 64 latents at every step. 8 heads, head dim 64.  3. **FFN:** Hidden dim 2048, GELU.  4. Pre-norm throughout.  5. Dropout 0.1.- Final linear projection: 512 → vocab_size (50,257)- **Weight tying:** The output projection matrix is shared with the input token embedding table. This saves ~25M parameters and typically improves performance.- Parameters: ~10M (excluding shared embedding)**Autoregressive generation:**- At inference, generate one token at a time.- At each step: embed all previously generated tokens, run decoder layers with causal mask, take the logit at the last position, sample or argmax, append to sequence, repeat.- Stop at `<|endofturn|>` token or max length.---## Parameter Count Summary| Component | Parameters ||---|---|| Token embedding (shared) | ~25.7M || Perceiver Encoder | ~10M || VQ Codebook | ~0.26M || Thinker Transformer | ~50M || Cross-Attention Decoder | ~10M || **Total** | **~96M** |This fits comfortably in the 12GB VRAM budget with room for batch size and optimizer state.---## TrainingTraining has three sequential stages. Do not skip stages or combine them.---### Stage 1: Codec Pretraining (Encoder + Decoder only)**Goal:** Prove the encoder and decoder can compress and reconstruct text through the latent bottleneck. The thinker does NOT exist in this stage — encoder output goes directly to decoder.**Data:** Any large clean text corpus. Recommended: a 10–20GB subset of OpenWebText or The Pile. Preprocess into chunks of max 512 tokens with a sliding window and 50% overlap.**Task:** Reconstruct the input. Given a chunk of text, encode it to 64 latent vectors, decode back to the same text. This is a seq2seq reconstruction task.**Decoder mode in Stage 1:** Non-autoregressive. The decoder predicts all output tokens in parallel (like BERT MLM but full sequence reconstruction). This eliminates the risk of the decoder ignoring latents by relying on causal token history. Causal self-attention in the decoder is DISABLED in this stage. Cross-attention to latents is the ONLY conditioning signal.**Loss:**```total_loss = reconstruction_loss + 1.0 * codebook_loss + 0.25 * commitment_lossreconstruction_loss = cross_entropy(predicted_tokens, original_tokens)  averaged over all token positions, ignoring padding```**Optimizer:** AdamW, lr=1e-4, weight decay=0.01, betas=(0.9, 0.95)**LR schedule:** Linear warmup for 2000 steps, then cosine decay to 1e-5.**Batch size:** As large as VRAM allows. Target 32–64 sequences per step. Use gradient accumulation if needed.**Stopping criterion:** Reconstruction loss plateaus and is meaningfully low (target <2.0 nats). More importantly: ablation test — zero out the cross-attention to latents (replace latent KV with zeros) and verify loss spikes significantly (>2x). If zeroing latents does not hurt reconstruction, the decoder has learned to ignore them and Stage 1 has failed. Debug before proceeding.**Checkpointing:** Save every 5000 steps. Keep last 3 checkpoints.---### Stage 2: Thinker Pretraining**Goal:** Train the thinker to operate in the latent space established by the codec.**Setup:** Load best Stage 1 checkpoint. Freeze encoder and decoder weights entirely. Insert thinker between encoder and decoder. Train only thinker weights.**Task:** Same reconstruction task as Stage 1. The thinker receives quantized encoder latents and must output latent vectors that the frozen decoder can decode into the original text. At the start, the thinker will learn to approximate the identity function — just pass the latents through. This is intentional and expected.**Loss:** Same as Stage 1. Only the thinker has gradients.**Optimizer:** AdamW, lr=1e-4, same schedule as Stage 1 (warmup + cosine).**Stopping criterion:** Loss should recover to approximately Stage 1 levels. If it can't, the thinker architecture has a problem.**Why this stage exists:** It forces the thinker to learn the geometry of the latent space before it is asked to do anything interesting with it. A thinker that has never seen the latent space will produce garbage outputs that break the frozen decoder.---### Stage 3: Joint Fine-tuning on Conversational Data**Goal:** Turn the system into an actual conversational assistant.**Setup:** Load best Stage 2 checkpoint. Unfreeze all weights. Enable causal self-attention in the decoder (this is the only architectural change between Stage 2 and Stage 3).**Data:** A small clean instruction-following / conversation dataset. Recommended: OpenHermes 2.5, UltraChat 200k, or similar. Filter to conversations under 512 tokens input + 256 tokens output.**Data format:**```<|user|> [user message] <|endofturn|> <|assistant|> [assistant response] <|endofturn|>```Multi-turn: concatenate all turns in order. The encoder sees the full conversation history up to the current assistant turn. The decoder generates only the current assistant turn.**Task:** Given conversation history as input, generate the assistant response. Standard language modeling loss on the assistant tokens only — do NOT compute loss on user tokens.**Loss:** Cross-entropy on assistant response tokens only.**Optimizer:** AdamW, lr=2e-5 (lower than Stage 1/2 — fine-tuning rate). Weight decay 0.01.**LR schedule:** Linear warmup 500 steps, cosine decay to 2e-6.**Stopping criterion:** Validation loss on held-out conversations. Stop when validation loss stops decreasing. Also do qualitative evaluation — actually chat with the model every few thousand steps.---## Inference```pythondef generate(model, tokenizer, conversation_history, max_new_tokens=256):    # Tokenize full conversation history    input_ids = tokenizer.encode(conversation_history)  # [seq_len]        # Encode to latents    token_embeds = model.embed(input_ids)               # [1, seq_len, 512]    latents = model.encoder(token_embeds)               # [1, 64, 512]    q_latents, _, _ = model.vq(latents)                 # [1, 64, 512]    thought = model.thinker(q_latents)                  # [1, 64, 512]        # Autoregressive decode    generated = [tokenizer.encode("<|assistant|>")[0]]    for _ in range(max_new_tokens):        dec_input = torch.tensor([generated])           # [1, current_len]        logits = model.decoder(dec_input, thought)      # [1, current_len, vocab]        next_token = sample(logits[:, -1, :])           # greedy or top-p        generated.append(next_token)        if next_token == tokenizer.encode("<|endofturn|>")[0]:            break        return tokenizer.decode(generated)```Sampling strategy for MVP: **top-p (nucleus) sampling**, p=0.9, temperature=0.8. Greedy decoding produces repetitive outputs.---## Monitoring & DiagnosticsThese must be logged every N steps (suggest N=100):| Metric | Why ||---|---|| `reconstruction_loss` | Primary training signal || `commitment_loss` | Should decrease and stabilize || `codebook_loss` | Should decrease and stabilize || `codebook_usage_pct` | Fraction of codebook entries active in batch. Alert if <30% || `latent_ablation_loss` | Loss when cross-attention to latents is zeroed. Should be >> reconstruction_loss || `latent_norm_mean` | Mean L2 norm of latent vectors. Sudden spikes = instability || `grad_norm` | Clip at 1.0 and log pre-clip norm |The `latent_ablation_loss` metric is the most important diagnostic. Run it every 1000 steps. If `latent_ablation_loss / reconstruction_loss < 1.5`, the decoder is ignoring the latents and training has failed silently.---## File Structure```latent_llm/├── model/│   ├── embedding.py         # Token embedding + positional encoding│   ├── encoder.py           #
